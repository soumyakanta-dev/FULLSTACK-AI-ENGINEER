[CLASS 01]: WHAT IS PYTHON AND MEMORY EXECUTION (RAM)

- CODE:

[CLASS 04]: TYPE CASTING & ADVANCED STRING SANITIZATION
- CONCEPT: Ek data type ko doosre data type me badalna (jaise text ko number banana)[cite: 15]. Real world 
  production applications me user input ko safely handle karne ke liye advance string methods use hote hain.
- CODE:
  raw_price = "   250   "
  clean_price = raw_price.strip()   # Output: "250" (Leading/Trailing spaces saaf karta hai)
  print(clean_price.isdigit())      # Output: True (Check karta hai ki string me sirf numbers hain)
  
  supplier_brand = "Amul"
  print(supplier_brand.isalpha())   # Output: True (Check karta hai ki text me sirf Alphabets hain)
  
  csv_data = "Oats,Milk,Paneer"
  parsed_list = csv_data.split(",") # Output: ['Oats', 'Milk', 'Paneer'] (String tod kar list banata hai)
- 💡 TIPS & TRAPS:
  * TRAP: VALUE-CRASH & SPACE TRAP! Agar user ne number ke aage-piche space dekar input kiya (jaise "  150  "), 
    toh direct .isdigit() fail ho jayega. Isliye conversion se pehle hamesha `.strip()` lagana compulsory hai[cite: 17].
  * TIP: Kisi bhi dynamic input parsing me .strip().lower() ya .strip().upper() ka combination sabse bullet-proof hota hai.

[CLASS 12]: COMPOSITE LISTS [] & DYNAMIC DELETION MECHANISMS
- CONCEPT: Ek single variable me bohot saare items line se store karna[cite: 44]. List mutable hai,

[CLASS 14]: DICTIONARIES {} & SAFE DICTIONARY AUDITING (.GET)
- CONCEPT: Data ko Key aur Value ke pair me store karna (jaise Mobile no : Name)[cite: 54]. Sabse

- CODE:

  * TRAP: KEY-ERROR CRASH! Traditional tarike se `store["price"]` mangne par agar key nahi milti, 
    toh live server par code instantly crash ho jata hai[cite: 56, 57]. Isliye production me humesha `.get()` ka use karein[cite: 58].
  * TIP: Keys hamesha unique hoti hain, duplicate key likhne par purani value override ho jayegi[cite: 59].

[CLASS 16]: FUNCTIONS DEFINITION & THE SCOPE CONTROL MECHANICS
- CONCEPT: Code ke ek hisse ko ek naam ke box me pack kar dena, taaki use jab chahein 
  wapas use kar sakein[cite: 64]. Functions ko use karte waqt variable scope ka dhyan rakhna zaroori hai.
- CODE:
  current_balance = 500  # Global Variable (Main RAM variable)
  
  def update_ledger():
      global current_balance  # Explicitly state validation permission grant!
      current_balance += 200  # Ab bahar ka variable change ho jayega
  
  update_ledger()
- 💡 TIPS & TRAPS:
  * TRAP: UNBOUNDLOCALERROR! Agar aap function ke andar bina `global` keyword declare kiye direct 
    bahar ke kisi variable ko change (`+=` ya `-=`) karne ki koshish karoge, toh Python code ko blast kar dega.
  * TIP: Functions ke andar banaye gaye normal variables sirf uske local scope tak hi zinda rehte hain, 
    function block se exit hote hi unka resources tabaah ho jata hai.

[CLASS 23]: EXCEPTION HANDLING LEVEL 1 (CRASH GUARD & RETRY LOOPS)
- CONCEPT: Runtime par hone wale unexpected data conversion crashes se code ko bachane 
  aur user se tab tak retry karwane ke liye jab tak sahi input na mile, try-except ko 
  while loop ke andar embed kiya jata hai.
- CODE:
  while True:
      try:
          user_birth_year = input('Enter your birth year :- ')
          birth_year = int(user_birth_year)
          user_age = 2026 - birth_year
          print(f'your age is {user_age}')
          break
      except Exception:
          print('Enter the correct number')
- 💡 TIPS & TRAPS:
  * TRAP: THE SKIP TRAP! Try block ke andar jaise hi kisi line par error aayega (jaise 
    int("Soumya")), Python uske neeche likhe saare codes (including the 'break' statement) 
    ko skip karke seedhe except block me kood jayega. Agar break skip hua, toh loop chalta rahega.
  * TIP: Jab tak user sahi valid input na de de, tab tak screen par warning dikha kar loop 
    chalate rehne ke liye yeh pattern industry standard mana jata hai.

[CLASS 24]: EXCEPTION HANDLING LEVEL 2 (SPECIFIC EXCEPTION ROUTING)
- CONCEPT: Professional applications me har galti par ek jaisa generic message dikhane 
  ke bajaye, errors ko unke technical naam (jaise ValueError, FileNotFoundError) se chun-chun 
  kar pakda jata hai taaki dynamic runtime par perfect context-aware backup pipelines 
  chalaye ja sakein.
- CODE:
  while True:
      filename = input('Enter your file name :- ')
      try:
          with open(filename, "r") as file:
              amount = int(file.read().strip())
              print(amount * .5)
              break
      except FileNotFoundError:
          print('File is mising bro...')
      except ValueError:
          print('data is corrupted in file.')
- 💡 TIPS & TRAPS:
  * TRAP: THE ORDER OF BLOCKS TRAP! Specific error blocks (jaise FileNotFoundError) ko hamesha 
    pehle likhna chahiye. Agar aapne sabse upar generic 'except Exception:' likh diya, toh 
    saare errors wahi trap ho jayenge aur niche ke specific blocks kabhi execute nahi honge.
  * TIP: File reading pipelines me database corruption pakadne ke liye humesha sub-level par 
    ValueError aur system missing ke liye FileNotFoundError ka direct combination use hota hai.
